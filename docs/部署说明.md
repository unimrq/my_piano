# 部署说明

本项目是纯静态网页，构建后仅需发布 `dist/`，不需要 API 服务或数据库。网页没有上传或导入入口；新曲谱由维护者或后台 AI 在源码环境通过命令行工具导入后重新构建，见 [服务端导入](服务端导入.md)。浏览器负责谱面、MIDI 与本地练习记录。

## Docker 部署

安装 Docker Engine / Docker Desktop 和 Compose，在项目目录执行：

```sh
docker compose up -d --build
```

打开 `http://localhost:8080/`。镜像内自动安装构建依赖，再将完整静态页面复制到 Nginx；宿主机不需要安装 Node.js。镜像默认收录 9 首：5 首 Noctave CC0 双手谱，以及《月亮代表我的心》《刻在我心底的名字（C调简单版）》《晴天》《青花瓷》4 首已有 MIDI。`.dockerignore` 仍排除浏览器测试记录、本地构建目录和安装包。

默认仅绑定 `127.0.0.1:8080`，不直接向外网开放。若明确需要局域网访问，可在 `.env` 设置 `PIANO_BIND=0.0.0.0`。容器使用 nginx 非 root 用户、只读根文件系统，临时文件仅写入 `/tmp`，移除 Linux capabilities 并禁止提权；不挂载宿主机目录或 Docker socket。如需修改，在项目目录的 `.env` 中填写 `PIANO_PORT=8081`，再重新启动。查看日志和停止服务：

```sh
docker compose logs --tail=100 piano
docker compose down
```

更新源码后再次运行 `docker compose up -d --build`，即可随新镜像看到默认曲库及已通过服务端工具收录的曲谱，联网刷新页面载入更新。生产 Nginx 容器没有 Node.js 导入工具，新增曲谱需先在源码或构建环境运行 `scripts/import-scores.cjs`。此前浏览器保存的曲谱、设置和练习记录仍在 IndexedDB 中；重建容器不会同步或备份这些浏览器数据。

电脑通过 localhost 可使用原生 MIDI。远程使用请接入 HTTPS，例如宿主机 Caddy 添加：

```caddyfile
piano.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Caddy 在另一容器运行时，不能用它自己的 `127.0.0.1` 访问本容器，应将两者加入同一 Docker 网络并代理到 `piano:8080`。不要用额外权限策略禁用 MIDI。

镜像构建会先执行核心测试，再生成网页。Compose 带健康检查，可用 `docker compose ps` 查看状态。仓库的 Docker 工作流会在 Linux 上构建镜像、启动容器，并检查静态资源、曲谱校验值、非 root 与只读权限；只做检查，不上传镜像或发布网站。本机未安装 Docker，运行结果见 [GitHub Actions](https://github.com/unimrq/my_piano/actions/workflows/docker.yml)。也可在容器启动后执行 `node tests/docker-smoke.cjs` 复查（此检查需要宿主机 Node.js）。配置采用 [Docker 多阶段构建](https://docs.docker.com/build/building/multi-stage/) 和 [官方 Nginx 镜像](https://hub.docker.com/_/nginx)。

历史结果：2026-10-29 的 [Linux Docker 实测](https://github.com/unimrq/my_piano/actions/runs/40905635483)针对当时仅收录 5 首 CC0、排除流行曲的版本。该次干净源码 68 项测试通过，2 项私人曲谱检查跳过；生产构建、容器健康检查、30 个静态资源、5 首公共曲谱 SHA-256、异常路径拒绝及容器权限检查均通过。本次默认收录 9 首的镜像以对应提交的工作流结果为准，不能沿用该旧结果。实际服务器 HTTPS、Windows Docker Desktop 和镜像系统包漏洞仍未验证。

## 本机使用

安装 Node.js 22.12 或以上版本，在项目目录运行：

```sh
npm ci
npm run build
npm run web
```

在同一台电脑打开 <http://localhost:4173/>。此地址可用于浏览器 MIDI 与离线缓存；不要直接双击 `dist/index.html`。服务默认只监听本机。需要局域网查看界面时显式运行 `npm run web -- --host 0.0.0.0`；可用 `npm run web -- --port 8080` 改端口。

同一局域网的其他设备可以用输出的 IP 地址查看页面，但 `http://局域网IP:端口` 不是标准安全上下文，原生 Web MIDI 和 Service Worker 不保证可用。远程或 iPad 日常使用建议采用下面的 HTTPS 站点。[安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

## 构建部署文件

公开部署建议从干净克隆构建：

```sh
git clone https://github.com/unimrq/my_piano.git
cd my_piano
npm ci
npm test
npm run build
```

上传 `dist/` 的**全部内容**，包含 `index.html`、`assets/`、`audio/`、`catalogue/`、`licenses/`、`sw.js`、图标和 Web App Manifest。不要上传源码、`node_modules` 或测试目录。生产服务器仅需静态文件服务，构建完成后无需安装 Node.js。

仓库和构建产物默认包含 9 首。5 首 CC0 原谱保留在 `public/catalogue/manifest.json`；4 首流行 MIDI 保留独立的 `src/personal-catalogue.json` 索引和 `public/catalogue/personal-*.mid` 文件，原曲目 ID 不变。服务端工具写入的新谱也使用后者索引，并复制到 `public/catalogue/imported-*`，构建后随站点提供。流行曲原曲及编配权利归原权利人，不适用项目 MIT 或公共谱 CC0，详见 [来源说明](../NOTICE.md)。

## 服务器 HTTPS：Caddy 示例

准备一个域名，将其 A/AAAA 记录指向服务器；开放 TCP 80、443 端口，安装 [Caddy](https://caddyserver.com/docs/install)。示例使用 `piano.example.com` 和静态目录 `/srv/my_piano/dist`，均需替换为自己的值。

1. 将完整 `dist/` 上传到 `/srv/my_piano/dist`，确保运行 Caddy 的用户可读取文件。
2. 参考仓库的 [deploy/Caddyfile](../deploy/Caddyfile)，合并到服务器现有 Caddy 配置中；已有其他站点时不要覆盖整个配置文件。
3. 检查并重载配置。以下命令适用于采用 Caddy 官方 systemd 服务的 Linux 服务器：

```sh
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

配置内容：

```caddyfile
piano.example.com {
    root * /srv/my_piano/dist
    encode zstd gzip
    header {
        Cache-Control "no-cache"
        X-Content-Type-Options "nosniff"
        Permissions-Policy "midi=(self), fullscreen=(self)"
    }
    file_server
}
```

配置域名并满足网络条件后，Caddy 自动申请和续期 HTTPS 证书，HTTP 会跳转 HTTPS。让 Caddy 的证书数据目录持久保存。这里直接提供静态文件，无需反向代理到 `npm run web`。[静态文件说明](https://caddyserver.com/docs/quick-starts/static-files)、[自动 HTTPS 条件](https://caddyserver.com/docs/automatic-https)

本例通过 `no-cache` 让浏览器重新校验文件，避免 `sw.js` 和入口页长期停留在旧版本；应用自己的 Service Worker 仍提供离线缓存。若沿用其他 Web 服务器，保留正确 JS/CSS MIME 类型，并避免用全局 `Permissions-Policy: midi=()` 禁止 MIDI。

## 可选：GitHub Pages

不使用服务器时，可以手动把构建产物发布到 GitHub Pages：

1. 本机从干净源码执行 `npm ci`、`npm run build`。
2. 将 `dist/` **里面的全部文件**放进单独的 `gh-pages` 分支根目录，并添加空的 `.nojekyll` 文件；保留 `main` 的源码。
3. 在 GitHub 仓库 Settings → Pages，选择 **Deploy from a branch**，分支选 `gh-pages`，目录选 `/ (root)`，保存。
4. 等待 GitHub 显示发布完成后，使用 Pages 设置页给出的 HTTPS 地址。若采用默认项目地址，本仓库地址为 `https://unimrq.github.io/my_piano/`，只有启用并成功发布后才可访问。

Vite 已使用相对资源路径 `base: "./"`，可放在域名根目录或 `/my_piano/` 子目录；子目录地址保留末尾 `/`。从分支发布时，直接选择源码 `main` 不会替你运行 Vite 构建。Pages 的可用性与仓库可见性、GitHub 套餐有关，Pages 内容通常公开可访问。[GitHub 官方发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

本仓库不自动启用 Pages，也没有推送即发布的工作流；上传源码和发布网站是独立操作。

## MIDI、iPad 与全屏

- Windows 优先使用 Chrome / Edge。钢琴连接**打开网页的设备**，设备设置中点击“连接钢琴”后授权 MIDI；服务器无需连接钢琴。
- 原生 Web MIDI 需要 HTTPS 或本机 localhost。域名站点应在顶层页面打开，避免被外层页面或 iframe 的权限策略拦截。[Web MIDI 接口说明](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/requestMIDIAccess)
- iPad Safari 尚不原生支持 Web MIDI；可以通过 MIDIWeb Browser 的桥接尝试 USB MIDI。网页的触摸布局已适配，真实 iPad 上的 MIDI、节拍器、全屏和休眠恢复仍需试弹验证。[MDN 兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/Navigator.json)
- 网页全屏依赖浏览器实现。应用全屏按钮不可用时，使用浏览器的全屏菜单；浏览器全屏与“添加到主屏幕”不会自动补上 MIDI 能力。

## 更新与离线缓存

拉取源码后重新执行 `npm ci`、`npm run build`，将整份新 `dist/` 发布为同一个站点。建议先上传到一个新目录，上传完成后再切换静态根目录并重载服务，避免用户读到一半新、一半旧的构建。

应用首次在线打开会在支持 Service Worker 的安全上下文缓存资源。联网刷新时优先读取服务器的新入口页，离线时使用最后完整缓存的版本；新资源完整下载成功后才能离线使用新版。新入口页不会覆盖旧版离线入口，避免更新中途断网时混用资源。不会为了更新自动打断正在进行的练习。[Service Worker 生命周期](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)

从旧版缓存机制升级时，若当前标签页仍显示旧界面，可先按 `Ctrl+F5` 强制刷新，等待离线资源更新后再刷新一次。之后的联网普通刷新会直接读取新版。可用 `node tests/offline-update.cjs` 验证普通刷新、失败更新回退及 IndexedDB 保留（需先安装 Chromium 测试浏览器）。

若仍显示旧界面，可在浏览器开发者工具中更新或注销本站 Service Worker，重新加载；需要时只删除本站 Cache Storage。**不要选择“清除所有站点数据”**，它会同时影响 IndexedDB 中的曲库和练习记录。

设置、记录及此前浏览器保存的曲库数据只存在当前浏览器。更换协议、域名、端口、浏览器或设备不会自动搬迁这些数据；服务器部署或 Git 推送也不会备份它们。当前没有完整数据导出入口，请保留源曲谱，不要用无痕窗口保存长期记录。

## 部署后检查

1. HTTPS 地址可正常打开，默认 9 首曲目及谱面资源可加载，包含 5 首 CC0 和 4 首流行 MIDI。
2. 在设备设置授权 MIDI，按键与踏板有反馈；自由跟弹不自动播放其他声部。
3. 确认网页没有上传、文件选择或拖放导入入口；选择已有曲目练习，刷新后设置和记录仍在。新增曲目按 [服务端导入](服务端导入.md) 操作，部署后确认能显示。
4. 完成首次资源缓存后，断网刷新；确认浏览器支持离线重载。
5. 顶栏切换“示范播放”，确认能听到曲子；未选 MIDI 输出时使用浏览器扬声器。完整缓存包含约 2 MB 的本地钢琴音色，离线后也应能播放。

自动浏览器测试使用模拟 MIDI；以上实际设备检查应在最终使用的电脑或 iPad 上完成。
