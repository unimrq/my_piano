# 网页版验证记录

日期：2026-10-29。本项目现在只维护网页版本，已移除 Electron 程序、桌面打包依赖及桌面专用检查。

## 本轮范围

- 保留 Web MIDI、IndexedDB 曲库、文件导入、浏览器全屏、谱面拖拽与循环、两种练习模式及记录。
- 浏览器检查使用标准 Playwright 缓存位置，可由 `PLAYWRIGHT_BROWSERS_PATH` 覆盖；截图及报告写入忽略 Git 的 `test-results/`。
- 增加本地运行、完整静态目录部署、Caddy HTTPS 及可选 GitHub Pages 说明。构建产物附带应用与第三方许可证。
- 公共源码只包含 5 首 CC0 双手谱。个人索引、流行曲原文件、旧截图、桌面测试数据与安装包不进入公开仓库。

- 本机核心测试 58 项通过，覆盖单音、和弦、重复音、踏板、错漏音、速度、循环、导入及曲谱文件校验。
- 从待发布源码快照安装依赖成功，未使用 `--legacy-peer-deps`；TypeScript 与 Vite 生产构建通过。公开源码 56 项测试通过，2 项依赖私人曲谱的检查按预期跳过。
- Chromium / Windows WebKit 横竖屏检查通过：曲库、谱面完整高度与垂直居中、点击定位、导入、模拟 MIDI 跟弹 100%、单手跟弹软件 NoteOn 为零、IndexedDB 重载恢复。Chromium 另验证真实触摸事件拖选循环和断网重载。

## 已有曲谱核对

本机《刻在我心底的名字》MIDI 已逐小节对照 EveryonePiano 12352／NGERN 的 C 调简单版纸谱，32 小节共 339 个起音的音高、节奏及合并连音时值相符。自动转谱第 21 小节末拍的一组三连音已修正，源 MIDI 与练习音符未改动。结论只针对该简易编配，个人曲谱不随公共源码发布。

- 导入默认生成缺失指法；已有曲目在练习设置内生成，可选三种手掌大小。保留原标注，排除伴奏、忽略声部；无法分配的组留空。只补缺失，不覆盖已生成的数字。
- 本机核心测试 65 项通过。新增覆盖双手、和弦用指顺序、锚点、重复音、按住手指占用、超出五指/跨度、XML 指法写回和原音符时序不变。
- Chromium / Windows WebKit 实际后台 Worker 生成与谱面数字显示、IndexedDB 保存和刷新恢复通过。《刻在我心底的名字》339/339 音获得建议；此为算法覆盖情况，不代表人工认可每个指法。

## 界面与安全收尾（2026-10-29）

- 移除快捷和弦及其保留音、设置和提示；白键上下两行显示固定 C 调简谱数字和音名，黑键不显示文字。曲库卡片标题与爱心对齐。指法仅在各行五线谱下方显示并统一基线，和弦保留必要堆叠。没有指法的旧曲目进入练习时自动生成一次。
- 已复现原本 Node 静态服务 `%00` 请求导致进程崩溃，修复后畸形路径返回 400 且服务继续响应。增加真实路径校验，阻止符号链接读取静态目录外的文件；拒绝隐藏文件、Windows ADS、非法路径和写入方法。静态服务默认只监听本机。
- 使用假数据临时目录验证 9 类路径输入、符号链接越界、GET/HEAD/POST、安全响应头及攻击后服务存活，均通过：`node tests/security-server.cjs`。
- MusicXML 入口拒绝实体声明、脚本、嵌入对象和事件属性；MXL 主文件必须是压缩包自身文件。新增攻击样例检查通过。曲目标题使用 React 文本，自动转谱对文本做 XML 转义；没有服务器上传、命令执行或用户数据查询接口。
- Node/Caddy/Nginx 配置提供防嵌套和限制表单提交的响应头。网页 CSP 保持本地资源、禁止内联脚本及动态 eval；允许内联样式是现有制谱和布局所需。GitHub Pages 等自定义响应头受限的托管环境不在相同防嵌套验证范围。
- Docker 配置使用非 root Nginx、8080 高端口、只读根目录、`/tmp` 临时目录、移除 capabilities、禁止提权；无宿主目录或 Docker socket 挂载。端口默认只绑定 127.0.0.1。本机没有 Docker；后续已通过 Linux CI 完成构建与运行检查，详见下方 Docker 实测，未进行镜像系统包漏洞扫描。
- 当前 63 项核心测试与生产构建通过，完整 npm 依赖审计（含开发依赖）未报告已知漏洞。Chromium/WebKit 指法生成、保存刷新及网页跟弹/导入/循环回归通过；Chromium 离线生成与重载通过。1280、768、390 像素宽度的标题/爱心对齐检查通过，双行键名与完整谱面截图已检查。
- 安全结论仅覆盖当前代码、上述本机测试和配置检查，不是“无漏洞”保证。应用的静态资源默认公开，个人曲库与记录保存在浏览器 IndexedDB；不同用户数据不在服务器端汇总。建议使用独立域名与 HTTPS，避免与不可信应用共享同一浏览器源。需要限制谁能访问整个站点时，应在反向代理层配置访问认证。

## 转谱、加载与音区自适应修复（2026-10-30）

- 同时起音、同时结束的 MIDI 音符合并为一个和弦，不再人为拆成多个相反符干的声部；真正重叠的独立声部保留。声部编号按整曲分配，跨小节延音保持编号。非标准组合时值使用合法音符与延音线表示，量化后落到下一小节的起音也能保留。
- 已复现本机《青花瓷》源 MIDI 1,355 个起音转为谱面后变成 1,357 个的问题：两处跨小节长音换了声部编号。修复后起音数恢复为 1,355。四首本机个人 MIDI 均完成音高、左右手、起音和结束时间的往返检查；普通音符量化误差不超过八分之一拍，原 MIDI 和练习时间保持不变。这不是与出版谱逐页校对的结论。
- 重画前移除旧的渲染容器，避免遗留空 SVG 导致尺寸测量错误或谱面被裁切。整曲只排版一次，调整区域高度时缩放现有 SVG；反馈先批量读取坐标，再更新颜色。原有谱面定位、滚动、循环与反馈保留。
- 首次进入时先补全缺失指法，再生成完整谱面；重新加载曲库会恢复已保存的建议，重新生成 MIDI 谱面时保留这些数字。暂停时停止无变化的下落图重绘与页面刷新。Windows Chromium 本机样例：《青花瓷》首次完整显示约 3.1 秒，刷新后约 1.5 秒；耗时随设备和曲谱变化，长曲仍需等待。
- 跟随音区改用真实经过时间；大跨度立即纳入，窄音域稳定 3 秒后恢复放大，不再受等待模式、暂停或向前跳转影响。自由练习同时考虑按住的键和最近 2.5 秒弹奏，避免逐音来回移动。最少白键数、锁定与完整键盘设置继续生效。
- 和弦指法在显示副本中简化：有标注的音里，右手显示最高音，左手显示最低音；保存的 MusicXML 和音符仍保留完整建议，单音不变。
- 核心测试 78 项通过。Chromium / Windows WebKit 检查通过：重画只留一个 SVG、上下完整和垂直居中、调整高度不重新排版、指法保存恢复、自由练习与暂停跟弹时的键盘放大恢复；原有导入、跟弹、循环和离线重载回归通过。实际 FP-30X 与 iPad 手感仍未复测。
